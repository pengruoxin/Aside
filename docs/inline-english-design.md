# 输入框内灰字 · 2026-10-30

用户要求继续实现输入框内浅灰英文，优先百度搜索框和微信聊天框，不占额外位置、不干扰原文输入。沿用原生输入法及离线生成，开发者选择透明文字覆盖层；不把译文写入 marked text 或宿主正文。

考虑的路线：写入组合文本会污染搜索、发送及撤销；浏览器扩展无法覆盖微信；使用原生非激活透明文字层，可以跨应用且不改写正文。因此采用第三种方式。它在实现上是透明窗口，但视觉上只有输入框内的灰字，没有浮窗边框、底色或额外布局空间。

浅灰文字默认显示在当前光标之后的同一行，仅占宿主已有空白，不覆盖原文、不挤动布局。完整英文放不下时允许单行省略，剩余空间少于80点时隐藏；不把文字搬到输入框外。讲解由输入法菜单或 Control–Option–E 按需展开。原候选显示可以在设置中选择，灰字模式不能安全定位时隐藏，不自动弹出额外候选框。

输入法接口提供光标行矩形，辅助功能接口提供当前可编辑输入框和窗口的可见边界。只能在宿主处于前台、输入框仍聚焦、原文及光标可核对、无拼音组合时显示。辅助功能未授权或应用没有暴露可靠位置时隐藏，并在设置提示原因。普通拼音及英文输入不需要辅助功能权限。只读当前聚焦控件的几何和选区，不修改辅助功能值，不读取聊天历史。

定位优先核对 IMK 光标与 AX 选区，查找聚焦文本框（包含 contenteditable 文本区）；为百度保留输入框右侧按钮安全余量，微信多行框仅使用当前行光标后的空间。限制必须来自实际控件边界，不能用整个浏览器或微信窗口推断输入框。窗口位置、焦点、选区或原文改变后隐藏；刷新跟踪仅在预览存在期间运行，停止打字之外不持续扫描。

灰字窗口无阴影、透明、不激活、不可成为键盘目标、鼠标穿透。继续输入、Esc、Return、编辑、切换输入源时立即收起。Return 仍提交原文一次；Tab 仅在英文输出模式、原文范围再次核对通过时采用英文。

验证分层：布局边界和坐标变换单元测试；真实 macOS 原生灰字绘制截图；已有 IMK / WebKit 原文及提交回归。CI 没有已登录微信，真实百度页可能不可访问，不能把模拟截图写成这些应用已验收。目标 M5 的辅助功能授权及实际应用适配继续明确待验收。现有0.3.0安装包不改写，新增代码先通过CI后另行交付。
